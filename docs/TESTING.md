## 1.8.3 重启后桌面操作续验（2026-10-15）

复现旧版点击主动作后停在辅助功能检查，系统开关虽开，应用实际未获授权。刷新同一应用的旧记录后，旧版继续失败于“调度中心的新建按钮不可用”，未启动成员应用。

修复判断条件：当前显示器的 mc.display 存在并不代表调度中心已展开；必须同时找到 mc.spaces.list 与 mc.spaces.add。缺少控件时重新打开调度中心，仍保留有界等待和创建／切换确认。

新增回归在旧条件上失败，在修复条件上通过。总计 262 项通过，覆盖残留显示节点、完整控件就绪和显示节点缺失。

刷新修复构建的授权后，同一工作组主动作实测成功创建及切换桌面，两名未运行成员启动后各一个普通窗口确认归入目标。没有改写工作组名单或图标布局，保留用户要求打开的应用及新桌面。

边界：没有再次重启整台 Mac，也没有删除既有桌面来强制构造单桌面环境。本轮实测确认了实际失败的权限和调度中心状态判断两阶段，不能据此声称所有重启或单桌面配置均已穷尽验证。升级临时签名构建仍可能需要刷新授权记录。

采用 K-008 分别验证权限、调度中心控件、创建切换和窗口归属。
